## 0. 目的

ユーザー要求は明確：

- Queryに **キャプション本文だけ** 入れる
- `[media attached: ...]` は不要
- システム由来ノイズ（添付案内文/メタ情報）も不要

本プランは「画像 + キャプション」入力時に、Recall Queryへ確実にキャプションだけを反映させる。

## 2. 根本原因（要約）

1. `normalizePromptAnchor()` の `raw_prompt_fallback` で media header が anchorに採用される。
2. `instantDeterministicRewrite()` 入口の dominant判定で、キャプション救済前に skip されるケースがある。
3. 結果として「認識はされたが query に採用されない」症状が発生する。

---

## 3. 方針オプション

### Option A（推奨）: 最小差分で「キャプション救済」を index + retriever の2点に追加

- anchor側: `raw_prompt_fallback` で media scaffold を除去してから tail抽出
- query側: dominant+empty時に caption-only 抽出を1段挟んで救済

**理由**: blast radius を抑えつつ、今回の症状に直接効く。

### Option B: attachment classifier を全面再設計

- 汎用性は高いが、変更範囲が広すぎて v0.4.29a には不向き。

### Fix A2 — `normalizePromptAnchor()` の raw fallback を caption優先化（既存関数流用）

対象: `src/index.ts`（L134〜138）

// 変更後
