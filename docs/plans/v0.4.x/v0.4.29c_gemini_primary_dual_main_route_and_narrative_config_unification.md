### Fix C4 — Google系クライアントへ共通設定を配線

対象: `src/gemini-direct-client.ts`, `src/narrative-worker.ts`

- `temperature`, `maxTokens`, `timeoutMs` を `narrativeConfig` 由来で適用
- Round 1 後半は GeminiDirectClient の `modelOverride="gemma-4-31B-it"` で Google 側モデル切替
- **⚠️ `reasoning.effort` → `thinkingConfig.thinkingLevel` へマッピング**: Gemini 3 シリーズ（gemini-3.1-flash-lite-preview 等）は `thinkingLevel`（minimal/low/medium/high）をサポート。`reasoning.effort` の low/medium/high をそのまま `thinkingLevel` へ送信。**`xhigh` は Gemini に存在しないため `high` へマップ**。`gemma-4-31B-it` も `thinkingLevel`（low/medium/high）をサポート（Google API 経由、ユーザー確認済）。Gemini 3 と同様に low/medium/high をそのまま送信
- **⚠️ `reasoning.maxTokens` → `thinkingConfig.thinkingBudget` へマッピング**: Gemini 2.5 シリーズ向け。ただし Gemini 3 と Gemma 4 では `thinkingBudget` は非推奨（予期しない性能低下の可能性）。Gemini 3 / Gemma 4 モデルでは `thinkingLevel` のみ送信し `thinkingBudget` は送信しない（公式ドキュメント準拠）
- **⚠️ Gemini API のキー名は `maxOutputTokens`**: `generationConfig.maxOutputTokens` に maxTokens を注入（OpenRouter の `max_tokens` とは異なる）。未設定(undefined)の場合は送信しない（Gemini API default に任せる）
- **⚠️ Gemini API の温度は `temperature`**: OpenRouter と同じキー名だが、有効範囲が異なる可能性に注意（ログで明示）
- **⚠️ `timeoutMs` は `GeminiDirectClient` コンストラクタ引数または AbortSignal で適用**: `generationConfig` 内ではなく外部で制御。`maxOutputTokens`/`temperature` とは適用先が異なるため混同注意
- **⚠️ `thinkingConfig` は `generationConfig` 内に配置**: REST API では `generationConfig.thinkingConfig.thinkingLevel` の階層

### 検証で発見したバグ（修正済み）

#### 🔴 BUG-1: `narrativizeWithGeminiModel()` 言語ゲート reask/handoff ルーティング欠落

**深刻度**: CRITICAL  
**発見方法**: 検証8（narrativizeWithGeminiModel 言語ゲート）  
**原因**: Gemini は以前 last-resort フェーズ（言語ゲート不要）だったが、v0.4.29c で primary フェーズ（6/6/3/3 の1番目）になったにも関わらず、言語ゲートの reask/handoff ルーティングと content-gate early bailout が追加されていなかった。  
**影響**: `narrativeLanguageOnFail=reask|handoff` 設定時、Gemini フェーズで言語不一致が検出されても無視され、最悪の場合 OpenRouter フォールバックまで不適切な出力が継続。content-gate reject も early handoff されず残りの試行を浪費。  
**修正**: `narrativizeWithModel()` の言語ゲートルーティングロジック（reask/handoff/softwarn）と content-gate early bailout（`contentRejectCount >= CONTENT_GATE_REJECTS_BEFORE_FALLBACK`）を `narrativizeWithGeminiModel()` にミラー。`languageReaskCount`/`contentRejectCount`/`currentUserMessage` の可変変数を追加。

#### 🔴 BUG-2: `maxTokens=0` が `maxOutputTokens:0`/`max_tokens:0` として送信

**深刻度**: CRITICAL  
**発見方法**: 検証9（GeminiDirectClient maxOutputTokens）  
**原因**: `openrouterConfig.maxTokens: 0` が `loadConfig()` で 0 として保持され（config 層では正しい）、それがそのまま `GeminiDirectClient` と `OpenRouterClient` に渡され `maxOutputTokens:0`/`max_tokens:0` として API に送信されていた。0 は「出力なし」を意味し、API が空のレスポンスを返す。  
**影響**: `maxTokens=0` を設定したユーザーは全ての物語化で空出力を受け取る。  
**修正**: 両クライアントで `maxTokens > 0` の時のみ `maxOutputTokens`/`max_tokens` を送信するガードを追加。`!== undefined && maxTokens > 0` に統一（`!= null` は不使用）。config 層は 0 を保持（観測性のため）、client 層でバリデーション（2層ガード）。
