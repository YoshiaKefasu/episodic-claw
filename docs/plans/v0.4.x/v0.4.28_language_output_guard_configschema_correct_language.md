# v0.4.28 — configSchema指定言語に強制する Narrative 出力言語ガード（CorrectLanguage 部分移植）

> Date: 2026-04-23  
> Status: 🟡 IMPLEMENTATION PLAN (Ready)  
> Strategy: **最小差分 / 既存ゲート拡張 / TS内完結**

---

## 0. 背景

ユーザー要件は明確です。

> `openclaw.plugin.json` の `configSchema` で指定した言語で、Narrative 出力を確実にガードしたい。

既存 v0.4.27b は「内容品質（generic/anchor）」を強化したが、**出力言語そのものの強制**は未実装。  
この v0.4.28 では Guardrails AI `CorrectLanguage` の設計思想（expected_language + threshold + on_fail）を、episodic-claw の既存構造へ最小差分で移植する。

## 2. 問題の本質（1文）

> 現行は「内容がそれっぽい」かは見ているが、「ユーザーが指定した言語か」は見ていないため、誤言語の narrative が保存され得る。

---

## 3. 方針（Decision）

## Option A（採用）
既存 `applyQualityGates()` の先頭に **Language Gate（G0）** を追加し、`configSchema` で言語強制を制御する。

- 追加キー:
  - `narrativeExpectedLanguage`
  - `narrativeLanguageThreshold`
  - `narrativeLanguageOnFail`
- on_fail:
  - `reask | handoff | softwarn | exception`
- 原則:
  - まず TSのみで完結（軽量）
  - 既存 retry/handoff 設計を壊さない

## Option B（不採用）
Guardrails の翻訳パス（HuggingFace/NLLB）まで丸ごと導入。

- 理由: 依存・運用コストが増えすぎる。v0.4.28 の目的（言語強制ガード）には過剰。

## 5. 実装計画（Fix A〜E）

### Fix A — configSchema 追加
`openclaw.plugin.json` に以下を追加。

```json
"narrativeExpectedLanguage": {
  "type": "string",
  "enum": ["auto", "ja", "en", "zh", "ko", "id"],
  "default": "auto"
},
"narrativeLanguageThreshold": {
  "type": "number",
  "minimum": 0,
  "maximum": 1,
  "default": 0.75
},
"narrativeLanguageOnFail": {
  "type": "string",
  "enum": ["reask", "handoff", "softwarn", "exception"],
  "default": "reask"
}
```

補足:
- `auto` は現行互換（言語強制なし）。
- 既存ユーザーを壊さないため default は後方互換優先。

### Fix B — 型/設定ロード
- `src/types.ts` に設定型を追加。
- `src/config.ts` `loadConfig()` で normalize。
  - `narrativeExpectedLanguage` default `auto`
  - `narrativeLanguageThreshold` は 0..1 clamp
  - `narrativeLanguageOnFail` 不正値は `reask`

### Fix C — Language Gate（G0）導入
- `src/narrative-worker.ts` `applyQualityGates()` の先頭に追加。
- 判定フロー:
  1. expected が `auto` なら pass
  2. `detectLanguage(text)` 実行
  3. mismatch 時に `onFail` 適用

onFail 動作:
- `reask`: 同 phase 再試行（補正指示付与）
- `handoff`: 早期 `null` で次 phase へ
- `softwarn`: warn ログのみで通過
- `exception`: 例外経路（既存 retry/queue に委譲）

### Fix D — `lang-detect` 拡張（threshold実装）
- 現行 `detectLanguage()` は confidence を返さない（`src/lang-detect.ts:31-55`）。
- `detectLanguageDetailed()` を追加し、`{ lang, confidence }` を返す。
- `narrativeLanguageThreshold` を G0 判定に適用。

> もし `eld` で confidence が安定しない場合:  
> v0.4.28 では `threshold` を soft-use（unknown時の補助判定）として扱い、厳密運用は v0.4.28b で強化。

### Fix E — テスト追加
- `test_narrative_quality_gate.ts` に language gate ケース追加:
  1. expected=ja / output=en → reject/reask
  2. expected=en / output=ja → reject/reask
  3. expected=auto → pass
  4. onFail=softwarn → pass + warn
  5. onFail=handoff → early handoff
  6. unknown ケース（短文・混在文）

## 7. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 短文で言語判定が不安定 | 中 | 初期は `softwarn` 観測→`reask` 段階導入 |
| CJK混在で誤判定 | 中 | `auto`/thresholdで緩和、ログ計測で閾値調整 |
| retry増加 | 低〜中 | mismatch時のみ発火、既存maxAttempts内で制御 |
