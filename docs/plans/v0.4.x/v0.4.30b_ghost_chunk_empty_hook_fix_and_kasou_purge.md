## 0. Executive summary

KASOU still produced a ghost narrative chunk after the v0.4.21 re-narrativization fixes.

The current evidence points to a different path than the original v0.4.21 bug:

```text
empty before_prompt_build from cron/hook
→ warm-start cursor path runs with msgCount=0
→ lastRecallTurnMessageCount becomes 0
→ later real prompt arrives with msgCount=616
→ warm-start guard no longer runs
→ segmenter treats old history as new
→ time-gap boundary flushes 114,512 tokens as live-turn
→ 3 cache chunks are enqueued
→ first chunk becomes ai-agent-development-log.md
```

The fix is to make empty prompt-build events a true no-op for cursor, segmenter, recall, and anchor injection state.

Production cleanup must also purge the already-created ghost episode and any matching ghost cache queue records that remain.

## 4. Root cause

### Primary root cause

Empty `before_prompt_build` events are treated as real first-turn events by `index.ts`.

This corrupts the warm-start lifecycle.

### Secondary root cause

`lastRecallTurnMessageCount` is doing two jobs:

1. duplicate recall guard for `assemble()`
2. first-run marker for segmenter cursor restoration

Those are different states and should not share one field.

### Tertiary risk

The already-enqueued ghost chunks remain in `cache.db`.

Even after code is fixed, stale queued / leased / backoff items can still narrativize later unless purged.

## 5. Source fix plan

### Fix 1 — add a dedicated segmenter cursor initialization flag

File: `src/index.ts`

Add a field to `AgentRuntimeState`:

```ts
/** True once non-empty messages have been used to initialize segmenter cursor state. */
segmenterCursorInitialized: boolean;
```

Initialize it in `getAgentState()`:

```ts
segmenterCursorInitialized: false,
```

Why:

- `lastRecallTurnMessageCount` should only mean “recall already ran for this message count”.
- Warm-start state needs its own flag.

### Fix 2 — make empty `before_prompt_build` a true no-op

File: `src/index.ts`

After resolving workspace and before any cursor restore, processTurn, recall, or anchor window decrement:

```ts
if (msgs.length === 0) {
  if (process.env.DEBUG_EPISODIC_RECALL_FINGERPRINT) {
    console.log(JSON.stringify({
      source: "episodic-claw",
      event: "empty-before-prompt-build-skip",
      agentId,
      agentWs,
      reason: "no_messages",
    }));
  }
  return {};
}
```

Important:

- Do not call `prepareWorkspaces()` just for an empty event unless a later code path truly needs it.
- Do not restore cursor.
- Do not call `bootstrapCursor()`.
- Do not call `processTurn()`.
- Do not call `retrieveRelevantContext()`.
- Do not decrement `anchorState.remainingEligibleAssembles`.
- Do not update `lastRecallTurnMessageCount`.

This is the main ghost-chunk fix.

### Fix 3 — factor segmenter cursor init into one helper

File: `src/index.ts`

Create a local helper inside plugin setup near `getAgentState()` helpers:

```ts
const ensureSegmenterCursorInitialized = async (
  state: AgentRuntimeState,
  msgs: Message[],
  agentWs: string,
  agentId: string,
): Promise<void> => {
  if (msgs.length === 0) return;
  if (state.segmenterCursorInitialized) return;

  const restoredCursor = await state.segmenter.restoreCursor(agentWs, agentId).catch(() => 0);
  if (restoredCursor > 0) {
    const clamped = Math.min(restoredCursor, msgs.length);
    state.segmenter.bootstrapCursor(clamped, "warm-start", agentWs, agentId);

    const walMessages = state.segmenter.walRestore(agentWs, agentId);
    if (walMessages.length > 0) {
      console.log(`[Episodic Memory] WAL restored ${walMessages.length} messages for ${agentId}. Injecting into buffer for idle flush.`);
      state.segmenter.injectWalRestoredMessages(walMessages, agentWs, agentId);
    }
  } else {
    const warmStartSkipMinMessages = cfg.warmStartSkipMinMessages ?? 50;
    if (warmStartSkipMinMessages > 0 && state.segmenter.currentCursor === 0 && msgs.length >= warmStartSkipMinMessages) {
      state.segmenter.bootstrapCursor(msgs.length, "warm-start", agentWs, agentId);
    }
  }

  state.segmenterCursorInitialized = true;
};
```

Use it before every non-empty `processTurn()` caller:

- `before_prompt_build`
- context engine `ingest()`
- `assemble()` fallback before its fire-and-forget `processTurn()`

Why:

- `before_prompt_build` is common, but not guaranteed to be the only path.
- `assemble()` currently has fallback segmentation.
- `ingest()` also calls `processTurn()` directly.

### Fix 4 — keep `lastRecallTurnMessageCount` strictly recall-related

File: `src/index.ts`

Only set it after non-empty recall work.

Recommended minimal guard:

```ts
if (msgs.length > 0 && recallOutcome.reason !== "no_messages") {
  state.lastRecallTurnMessageCount = msgs.length;
}
```

Because Fix 2 returns early for empty events, this is a second safety net.

### Fix 5 — add structured observability

File: `src/index.ts`

Add logs for:

- `empty-before-prompt-build-skip`
- `segmenter-cursor-init-restored`
- `segmenter-cursor-init-warm-start-skip`
- `segmenter-cursor-init-fresh-small-context`

Keep logs short and gated where noisy.

Suggested non-noisy log:

```ts
console.log(JSON.stringify({
  source: "episodic-claw",
  event: "segmenter-cursor-init",
  agentId,
  msgCount: msgs.length,
  restoredCursor,
  action,
}));
```

## 6. Optional hardening: cache purge RPC

This is optional but recommended for safe production cleanup.

Current cache queue has `Ack`, `Retry`, and `Requeue`, but no explicit purge by ID.

Evidence:

- `go/internal/cache/queue.go` has `updateItemByScan(..., deleteAfter bool)` and supports delete internally.
- `go/main.go` exposes `cache.ack`, `cache.retry`, `cache.requeue`, but not `cache.delete` / `cache.purge`.

### Option A — add first-class purge RPC (recommended)

Add to `go/internal/cache/queue.go`:

```go
func (q *Queue) Purge(id string) error {
    q.mu.Lock()
    defer q.mu.Unlock()
    return q.updateItemByScan(id, func(item *QueueItem) bool {
        return true
    }, true)
}
```

Add to `go/main.go`:

```go
func handleCachePurge(conn net.Conn, req RPCRequest) {
    var params struct {
        ID string `json:"id"`
    }
    // validate ID, scan cacheQueues, call q.Purge(params.ID), respond
}
```

Register method:

```go
case "cache.purge":
    go handleCachePurge(conn, req)
```

Add to `src/rpc-client.ts`:

```ts
async cachePurge(id: string): Promise<string> {
  return this.request<string>("cache.purge", { id });
}
```

Why recommended:

- Avoids direct PebbleDB surgery.
- Uses existing queue locking.
- Gives a repeatable operational cleanup path.

### Option B — offline DB surgery (not recommended unless urgent)

Stop gateway, back up `cache.db`, then use a small Go utility to open Pebble and delete exact keys.

Do not use shell `rm` or ad-hoc text tools against PebbleDB files.

Risk:

- Higher chance of corrupting queue state.
- Less auditable than an RPC method.

## 11. Risks and trade-offs

| Risk | Impact | Mitigation |
|---|---|---|
| Empty events may have carried useful anchor text | Anchor injection window no longer decrements on empty events | Correct behavior: empty prompt is not a real turn. Non-empty prompt still gets anchor. |
| Warm-start threshold may skip a legitimate long first conversation | Could miss initial segmentation for a huge new session | Existing threshold behavior already makes this trade-off. Keep default 50 and document it. |
| Cache purge RPC adds destructive capability | Wrong ID could delete queue item | Restrict to exact ID, log every purge, no wildcard support. |
| DB cleanup on KASOU could corrupt state if done live | Memory loss / queue corruption | Stop gateway, backup first, prefer RPC / Go code over raw file edits. |

## 12. Pro recommendation

Choose the simple path:

1. Implement Fix 1–5 in `index.ts`.
2. Add tests for empty-first-hook and empty-then-huge-history.
3. Add `cache.purge` only if KASOU still has ghost queue items after inspection.
4. For production cleanup, stop gateway, back up, purge exact IDs, quarantine the `.md`, and verify recall.

Do not redesign the whole segmenter.

The bug is not in surprise scoring or narrative quality gates.

The bug is the lifecycle boundary: an empty hook was allowed to act like a real turn.
