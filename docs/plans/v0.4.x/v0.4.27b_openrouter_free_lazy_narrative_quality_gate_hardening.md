## 2. 問題の本質（1文）

> 現行ゲートは「形式的に narrative っぽい抽象文」を通してしまい、実務上必要な具体情報を含まない物語が保存される。

## 3. 方針（Decision）

### Option A（採用）
**最小差分で `narrative-worker.ts` に「内容品質ゲート」を1段追加する。**

既存の Gate1-3（圧縮率/echo/形式）は維持し、次を追加:

1. **Anchor Coverage Gate（新規）**
   - raw text から「具体アンカー」を抽出（例: エラーコード、ファイル名、コマンド、数字/時刻、固有トークン）。
   - narrative 側に最低限のアンカー再登場を要求。
   - 条件例:
     - raw から抽出アンカー数 `>=4` の場合、narrative で `>=2` 個一致を必須。
     - 抽出アンカーが少ない雑談は strict 適用しない（誤検知防止）。

2. **Generic Template Gate（新規）**
   - 既知のテンプレ抽象句（JP/EN）を先頭〜中盤で検知して reject。
   - 初期辞書は今回の実害に合わせて最小セットで開始（YAGNI）。

3. **観測ログ（新規）**
   - reject 理由を `narrative-content:*` として出力。
   - どの gate が弾いたかを運用ログで追跡可能にする。

4. **Exam-style Prompt Contract（補助）**
   - `DEFAULT_USER_PROMPT_TEMPLATE` を「採点条件付きの設問」形式へ強化。
   - 例: 「会話履歴を第三者過去形で物語化し、最低3つの具体アンカー（ファイル名/コマンド/数値/エラー）を自然文に含めること」
   - ただし **prompt 単体では不十分**。最終判定は Gate 側で行う（Prompt + Gate の二段構え）。

### Option B（不採用）
Gemini direct の常時強制（free フェーズを全面回避）

- コスト/依存が増え、`GEMINI_API_KEY` 未設定環境で劣化。
- 根本は品質判定不足なので、まず gate 補強を優先。

## 4. 実装計画（最小差分）

### 4.1 変更ファイル

- （必要なら）`docs/plans/v0.4.x/v0.4.27b_...md` の PassOff 更新

### 4.2 Fix A — Anchor Coverage Gate を追加（Gate 4）✅
1. `extractContentAnchors(rawText: string): string[]` を追加
   - 正規表現ベースで軽量抽出（ファイルパス/拡張子、HTTPステータスコード、エラーコード、バージョン文字列、camelCase識別子）。
2. `countAnchorHits(narrativeText, anchors)` を追加 — 大文字小文字無視で部分一致
3. `applyQualityGates(...)` に Gate 4 として挿入
   - reason: `narrative-content: low-anchor-coverage`
   - **乖離4修正**: 閾値を Prompt と整合 → `rawAnchors >= 4` の時 `narrativeHits >= 3` 必須（Prompt も `>=3` を要求）
   - `contentGateEnabled=true` の時のみ活性（フォールバック phase が存在する場合のみ）

### 4.3 Fix B — Generic Template Gate を Gate 3b として追加 ✅
1. `GENERIC_TEMPLATE_PHRASES` 定数を DRY 単一ソースとして定義（乖離2修正）
   - JP 9句 + EN 5句 = 14パターン
2. `applyQualityGates` 内に Gate 3b として body-scan（先頭300文字）を実装
   - `checkNarrativeFormat` Gate 3 (firstLine-only) とは別スコープ
   - Gate 3b は `isContentGate=true` → early bailout ルーティングに参加
   - reason: `narrative-content: generic-template phrase "..." detected in body`

### 4.4 Fix C — フォールバックルーティング（乖離3修正 — 最重要）✅
1. `RetryPhase.contentGateEnabled` フィールド追加
   - `true` = フォールバック phase が存在する（content gate reject → phase handoff 安全）
   - `false` = フォールバックなし（content gate skip → 現行挙動維持、アイテム喪失防止）
2. `getRetryPhases()` 再構築:
   - `openrouter/free` デフォルト + GEMINI_API_KEY あり → 2 phase（primary + fallback-gemini-content）
   - `openrouter/free` デフォルト + GEMINI_API_KEY なし → 1 phase（content gate 無効、現行挙動維持）
   - カスタム primary → 既存 multi-phase（content gate 有効）
3. `QualityGateResult` 型導入: `{ pass, reason, isContentGate }`
   - `isContentGate=true` の gate reject は early bailout 対象
4. `narrativizeWithModel`: `contentRejectCount` 追跡
   - `CONTENT_GATE_REJECTS_BEFORE_FALLBACK=3` 回到達で `null` 返却 → phase handoff
5. `narrativizeWithGeminiModel`: `contentGateEnabled=false`（最後の砦、content gate なし）

### 4.5 Fix D — Exam-style Prompt Contract ✅
1. `DEFAULT_USER_PROMPT_TEMPLATE` に「試験問題」スタイルの要件を追加:
   - 必須要件: 具体アンカー `>=3` を narrative 文中に反映（Gate 4 閾値と整合 — 乖離4修正）
   - 減点要件: 抽象テンプレ句禁止（"It is crucial", "自然な流れを心がけ"）
   - 出力形式: narrative 本文のみ（チェックリストや自己採点を出力しない）
2. 役割分担:
   - Prompt = 生成の誘導
   - Gate = 保存前の強制判定（最終防波堤）

### 4.6 運用観測ログ ✅
- Gate 3b / Gate 4 の reject で `narrative-content:*` reason を出力
- anchor coverage パス時は info ログで hits/total を出力
- early bailout 時は warn ログで contentRejectCount と attempt を出力

#### Option A — プラン修正版（Anchor Gate + Gate3拡張 + フォールバックルーティング） *(推奨)*
**Approach**: プランの方向性は正しいが、3つの乖離を修正し、**最も重要な修正**として content gate reject 時のフォールバックルーティングを追加する
**Implementation cost**: Low-Medium
**Risk**: Low
**Why recommended**: 乖離3（リトライ無駄打ち→アイテム喪失）は **現行より悪化する回帰** なので必須対応。他2点は最小差分で解決可能
**Concrete steps**:
1. `extractContentAnchors(rawText)` 追加 — regex ベース軽量抽出（ファイルパス/拡張子、HTTPステータスコード、エラーコード、数字付きトークン、英字コマンド）
2. `countAnchorHits(narrativeText, anchors)` 追加 — 大文字小文字無視で部分一致

   - reason: `narrative-content: low-anchor-coverage`
4. Gate 3 の `assistantPhrases` リストに今回の実害パターンを追加（**乖離2修正 — DRY**）
   - JP: 「地の文を整え」「心がけました」「不可欠です」「精密な調整」
   - EN: generic academic phrases from `narrative-fact-balance-precision.md`
   - Generic Template Gate は独立 Gate としてではなく Gate 3 拡張として実装
5. **[乖離3修正] content gate reject 時のフォールバック強制ルーティング**: `getRetryPhases()` を修正し、content gate 連続不合格時に Gemini direct への強制移行を追加

6. Prompt と Gate の閾値整合（**乖離4修正**）: Prompt「≥3」→ Gate「≥2 of ≥4」は Gate 側を Prompt に合わせる。`rawAnchors >= 4` の時 `narrativeHits >= 3` に変更。または Gate 閾値をそのままにし Prompt を Gate に合わせる（Gate が権威）
7. §4.1 の `test_phase4_5.ts` 参照を削除（**乖離1修正**）
8. 運用観測ログ: `narrative-content:*` reason を gate reject ログに追加
