## 0. 目的

v0.4.22c の実装後に発見された **2件の実害あるWAL回帰バグ** を修正する。

---

## 1. バグの詳細（ソース証拠）

### BUG-A (HIGH) — `afterCompaction` から `walClearAll` が消えている

**現状:** `segmenter.ts:836-843`
```typescript
afterCompaction(agentWs: string = "", agentId: string = ""): void {
    this.pendingCompactionSkip = true;
    this.buffer = [];
    this.resetBufferTokens();
    this.turnSeq = 0;
    this.clearIdleFlushTimer();
    // ← walClearAll がない
    console.log(JSON.stringify({ source: "episodic-claw", event: "after-compaction", ... }));
  }
```

**v0.4.22b ではあった:**
```typescript
if (agentWs && agentId) {
  this.walClearAll(agentWs, agentId);
}
```

v0.4.22c の `resetBufferTokens()` 追加時に誤って削除された。

**影響:** compaction後もWALファイルが残り、次回warm-startで compaction前の古いメッセージが復元される。

---

### BUG-B (MED) — WAL scan のパターンが raw agentId を使っている

**現状:** 3箇所で raw `agentId` をパターンに使っている:

| 箇所 | 行 | コード |
|------|-----|--------|
| `walRestore` | L287 | `const stagedPattern = '.episodic-wal.${agentId}.flush-';` |
| `injectWalRestoredMessages` | L371 | `const stagedPattern = '.episodic-wal.${agentId}.flush-';` |
| `walClearAll` | L336 | `const stagedPattern = '.episodic-wal.${agentId}.flush-';` |

ファイル作成は `getWalActivePath` / `getWalStagedPath` 経由で `safeId`（サニタイズ済）を使うが、**scan時はraw `agentId`** を使っている。

`agentId = "main"` なら問題ない。しかし特殊文字が含まれる場合、scanがファイルを見つけられない → staged WALが残り続ける。

**修正:** scan箇所でも `agentId.replace(/[^a-zA-Z0-9_-]/g, "_")` を使う。

---

### EDGE-1 (LOW) — warm-start フォールバックで WAL 復元スキップ

`index.ts:981-983` のフォールバックパス（cursor=0、50件以上）で `walRestore` が呼ばれない。
cursor未永続化のままクラッシュした場合、WALにデータがあっても復元されない。
ただし cursor は3ターンに1回永続化されるため、50件以上で cursor=0 のままクラッシュする確率は極めて低い。

**今回は見送り（YAGNI）。** 確率が低く、修正が `index.ts` に及ぶため分離する。

## 2. 修正内容

### 2.1 BUG-A — `afterCompaction` に `walClearAll` を復元

```diff
  afterCompaction(agentWs: string = "", agentId: string = ""): void {
    this.pendingCompactionSkip = true;
    this.buffer = [];
    this.resetBufferTokens();
    this.turnSeq = 0;
    this.clearIdleFlushTimer();
+   // [v0.4.22d] WAL: compaction後は会話が再構成済みのためWALも明示クリア
+   if (agentWs && agentId) {
+     this.walClearAll(agentWs, agentId);
+   }
    console.log(JSON.stringify({ source: "episodic-claw", event: "after-compaction", pendingSkip: true, bufferCleared: true }));
  }
```

### 2.2 BUG-B — WAL scan のパターンに safeId を使用

3箇所とも同じ修正パターン:

```diff
- const stagedPattern = `.episodic-wal.${agentId}.flush-`;
+ const safeId = agentId.replace(/[^a-zA-Z0-9_-]/g, "_");
+ const stagedPattern = `.episodic-wal.${safeId}.flush-`;
```

対象箇所:
1. `walRestore` 内の staged scan
2. `injectWalRestoredMessages` 内の staged check
3. `walClearAll` 内の staged scan
