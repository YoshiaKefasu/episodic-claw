# v0.4.30d Go Sidecar Gemma Model Name Fix

## 発端

KASOU Debian 13 移行後、Episodic-Claw v0.4.30c のログに以下のエラーが確認された:

```
1:51:14 warn [background] [info] Replay review failed for episodic-claw-release-v031: API error (status 404): {
  "error": {
    "code": 404,
    "message": "models/gemma-3-27b-it is not found for API version v1beta, or is not supported for generateContent. Call ListModels to see the list of available models and their supported methods.",
    "status": "NOT_FOUND"
  }
}
```

`gemma-3-27b-it` が Google Gemini API で 404 Not Found。このモデル名は Google 側から削除されたか名称変更された可能性が高い。

## 問題

v0.4.30a で TS 側 (`narrative-worker.ts`) のモデル名を `gemma-4-31b-it` に修正したが、**Go サイドカー側は修正漏れ**だった。

### 影響を受けるファイル（3箇所）

| ファイル | 行 | 現在のコード | 役割 |
|---|---|---|---|
| `go/main.go` | 2013 | `ai.NewGoogleStudioProvider(apiKey, "gemma-3-27b-it")` | Async Healing Worker（非同期修復） |
| `go/internal/vector/replay.go` | 660 | `ai.NewGoogleStudioProvider(apiKey, "gemma-3-27b-it")` | Replay Scheduler（リプレイレビュー） |
| `go/internal/vector/consolidation.go` | 39 | `ai.NewGoogleStudioProvider(apiKey, "gemma-3-27b-it")` | D1 Consolidation（D1統合） |

### 影響を受けるバックグラウンド処理

1. **Replay Scheduler** (replay.go) — エラーログの直接原因。定期リプレイレビューが機能せず、全エピソード D1 昇格が止まる
2. **D1 Consolidation** (consolidation.go) — D0→D1 タイトル・スラッグ・サマリー生成が機能せず、エピソード構造が未完成のまま
3. **Async Healing Worker** (main.go) — エピソードの非同期修復（429 フォールバック後の再処理）が機能しない

いずれも silent failure（エラーログは出るが処理はスキップされ続ける）なので、気付きにくいバグ。

## 修正

### Fix 1: 3ファイルのモデル名を一括置換

`gemma-3-27b-it` → `gemma-4-31b-it`

**根拠:**
- TS側 `narrative-worker.ts` の `GEMMA_DIRECT_MODEL = "gemma-4-31b-it"` と統一する
- `gemma-4-31b-it`（小文字 b）は Google Gemini API で有効なモデル名（v0.4.30a で確認済み）
- 全てのバックグラウンド処理で同じモデルを使って問題ない（むしろ統一すべき）

```diff
- gemmaProv := ai.NewGoogleStudioProvider(apiKey, "gemma-3-27b-it")
+ gemmaProv := ai.NewGoogleStudioProvider(apiKey, "gemma-4-31b-it")
```

該当ファイル:
- `go/main.go` L2013
- `go/internal/vector/replay.go` L660
- `go/internal/vector/consolidation.go` L39

### Fix 2: 未使用の embedding モデル名も確認

`consolidation.go` L40 と `main.go` L2014 は `gemini-embedding-2-preview` を使用している。このモデルがまだ有効か確認する必要があるが、現時点ではエラーログが出ていないため、この PR では修正対象外とする。

## リグレッションチェック

### 確認済み（非問題）

1. **Go サイドカーは TS から別プロセスで動作** — model 名の string は `NewGoogleStudioProvider()` に渡されるだけで、他に依存なし。単なる string リテラル変更のためリグレッションリスクは極めて低い。

### 注意点

1. **Go サイドカーの再ビルドが必要** — ソース変更のため、`go build` でバイナリを再生成する
2. **クロスコンパイル** — KASOU は Linux amd64 なので `GOOS=linux GOARCH=amd64` でビルド
3. **デプロイ** — 新しい `episodic-core` を KASOU の `~/.openclaw/extensions/episodic-claw/dist/` に配置し、gateway 再起動

## テスト

Go 側の単体テストで model name の検証は行わない（Mock が API コールを差し替えるため実害なし）。既存の Go テストがパスすれば OK。

```bash
cd go
go test ./... 2>&1
```

TS 側のテストは変更がないため、フルスイート実行は不要（念のため走らせても良い）。

## リリース判断

- **TS コードに変更なし** → `package.json` のバージョン更新は不要（hotfix として v0.4.30c のまま Go バイナリだけ差し替えてもいい）
- ただし、トレーサビリティのために **v0.4.30d** としてフルリリース推奨（GitHub Release + ClawHub）
- ClawHub semver マッピング: `v0.4.30d` → `0.4.30-hotfix.4`

### 検証結果

- **Go テスト**: 全パス（`episodic-core` / `internal/ai` / `internal/state` / `internal/vector`）
- **TS テスト**: 変更なし（Go コードのみの修正）

### リグレッション懸念

確認済み — 以下の理由からリグレッションリスクは極めて低い:

1. `NewGoogleStudioProvider()` の model name 引数は API リクエストの URL パスに埋め込まれるだけ（`/models/{modelName}:generateContent`）
2. `gemma-4-31b-it` は v0.4.30a で TS 側が既に 1ヶ月以上実運用しているモデル名
3. 3箇所の変更は全て同一パターンの string リテラル置換
