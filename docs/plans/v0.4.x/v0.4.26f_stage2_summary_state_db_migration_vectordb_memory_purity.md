### 📎 Supplementary Notes

**wsHash cross-language risk detail**:  
JS `charCodeAt(i)` returns UTF-16 code units (0–65535). Go `rune` iteration yields Unicode code points (0–0x10FFFF). For paths containing non-BMP characters (rare but possible in CJK user directories), the hash outputs will diverge silently. Even for ASCII-only paths, `int` overflow semantics differ: JS `(hash << 5) + hash + charCode` produces a float64 that is then masked with `& 0x7FFFFFFF`; Go `int` arithmetic is 64-bit on most platforms and would need explicit `& 0x7FFFFFFF` at the same point. The plan's "fixture test" requirement is necessary but insufficient — the implementation itself must be proven equivalent for all edge cases, which is a non-trivial verification effort disproportionate to the migration's benefit.
