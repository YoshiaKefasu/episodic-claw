## 1. 問題の概要

`recallQueryRecentMessageCount=2` 設定時、最新ユーザーメッセージのキーワードがrecallクエリから完全に脱落する現象。

### 根本原因（v0.4.23 Phase 1 観測で確定）

**仮説A「クエリリライトの偏り」が確定。** 仮説B（タイミング問題）は否定された。

### v0.4.23 観測ログ（決定的証拠）

```
before-prompt-build-arrival:
  msgCount: 500
  last3Roles: [assistant, user, assistant]
  lastUserPreview: "じゃあ 毎日 何枚か手書きをすればいいですよね?"

recall-window-fingerprint:
  fingerprints:
    idx=0: rawLen=181, preview="Kasou 相談したいんですけど あの 僕は前がその漢字が書けるんですけど..."
             perMsgKeywords: ["相談", "僕", "前", "漢字", "書ける", "初期"]
    idx=1: rawLen=24,  preview="じゃあ 毎日 何枚か手書きをすればいいですよね?"
             perMsgKeywords: ["毎日", "枚", "手書き", "すれ", "いい"]

  latestUserInWindow: true
  latestUserPreview: "じゃあ 毎日 何枚か手書きをすればいいですよね?"

recall query: "相談 僕 前 漢字 書ける 初期 日本語 勉強 Kasou"
  → idx=0のキーワードが多数。idx=1のキーワード「毎日」「手書き」が1つも含まれていない
  → reason: recall_empty
```

### 因果連鎖

1. `instantDeterministicRewrite()` は2件の eligibleText を `join("\n")` で1本の文字列に連結する
2. `extractPolyglotKeywords()` は連結された文字列全体から keyword を抽出する
3. CJK-dominant の場合、`primaryCount=8` 席が **前から順** に埋まる
4. idx=0（181文字の長いメッセージ）が CJK キーワードを多数産出し、8席のうち6席を独占
5. idx=1（24文字の短いメッセージ）の CJK キーワード「毎日」「手書き」は席を奪われて脱落
6. 結果: 最新メッセージの語がクエリから完全消失

### `latestUserPreview` が1つ前のメッセージを示す件

`lastRole: "assistant"` と `last3Roles: ["assistant", "user", "assistant"]` から、`before_prompt_build` 発火時点で配列末尾はエージェントの返信である。今回の観測ログでは、ユーザーの最新発言はまだ配列に追加されていないように見える。`latestUserPreview` は「配列内で最も新しいユーザーメッセージ」を示すものであり、「UI上で今送ったメッセージ」とは限らない。

## 2. Fix: Message-Aware Keyword Reservation

### 設計方針

**最も古いメッセージではなく、最も新しいメッセージのキーワードが優先されるべき。**

「最新メッセージ = ユーザーが今最も関心のある話題」という前提に基づく。
古い長文が前半席を独占するのを防ぎ、最新メッセージに**予約席**を確保する。

### 変更概要

**ファイル**: `src/retriever.ts` — `instantDeterministicRewrite()` 関数

**Before** (v0.4.22):
```typescript
// 現行: 2件を join("\n") → 1本の文字列 → extractPolyglotKeywords → 先着順で席埋め
const cleaned = eligibleTexts
  .map(text => text.replace(...).replace(...).trim())
  .filter(Boolean)
  .join("\n");
const keywords = await extractPolyglotKeywords(cleaned, config);
```

**After** (v0.4.24):
```typescript
// 新版: メッセージごとにキーワード抽出 → newest-first → 予約席確保 → dedupe → 結合
const perMessageKeywords: string[][] = [];
for (const et of eligibleTexts) {
  const kws = await extractPolyglotKeywords(et, config);
  perMessageKeywords.push(kws);
}
// 最新メッセージ（配列末尾）のキーワードを優先
const reversed = [...perMessageKeywords].reverse();
const LATEST_RESERVE = 4; // 最新メッセージに最低4席を予約
const MAX_TOTAL = 12;      // クエリ全体の最大語数

const seen = new Set<string>();
const result: string[] = [];

// スロット1: 最新メッセージのキーワード（予約席）
for (const kw of reversed[0]) {
  if (result.length >= LATEST_RESERVE) break;
  const lower = kw.toLowerCase();
  if (!seen.has(lower)) {
    seen.add(lower);
    result.push(kw);
  }
}

// スロット2: 2番目以降の古いメッセージ
for (let i = 1; i < reversed.length && result.length < MAX_TOTAL; i++) {
  for (const kw of reversed[i]) {
    if (result.length >= MAX_TOTAL) break;
    const lower = kw.toLowerCase();
    if (!seen.has(lower)) {
      seen.add(lower);
      result.push(kw);
    }
  }
}

// スロット3: まだ席がある場合、最新メッセージの残りキーワード
for (const kw of reversed[0]) {
  if (result.length >= MAX_TOTAL) break;
  const lower = kw.toLowerCase();
  if (!seen.has(lower)) {
    seen.add(lower);
    result.push(kw);
  }
}

// fallback: per-message 抽出で語が得られなかった場合、cleanedPerMessage を結合して返す
const fallbackText = cleanedPerMessage.join("\n");
return result.length > 0 ? result.join(" ") : fallbackText;
```

### キーポイント

| 項目 | 説明 |
|---|---|
| **最新予約席** | 最新メッセージに最低4席（`LATEST_RESERVE=4`）を確保。12席中33% |
| **newest-first** | キーワード抽出後、配列をreverseして最新から処理 |
| **dedupe** | `seen` Set で重複語を排除（大小文字区別なし） |
| **スロット3** | 古いメッセージで席が埋まらなかった場合、最新メッセージの残りキーワードで埋める |
| **YAGNI** | `LATEST_RESERVE` と `MAX_TOTAL` はハードコードではなく `config` 化の余地ありだが、まずは定数で実装 |
| **後方互換** | `recallQueryRecentMessageCount=1` の場合、1件だけのキーワード抽出になるので現在と同じ動作 |

### スロット配分の例

**修正前（v0.4.22）**:
```
クエリ: "相談 僕 前 漢字 書ける 初期 日本語 勉強 Kasou"
                                   ↑ idx=0のキーワードが全席を独占
                                   ↑ idx=1の「毎日」「手書き」が完全脱落
```

**修正後（v0.4.24）**:
```
スロット1（最新予約席）: "毎日" "手書き" "すれ" "いい"  ← idx=1から最低4語
スロット2（古いメッセージ）: "相談" "漢字" "初期" "書ける" "日本語" "勉強" ← 残り席
スロット3（最新残り）: "僕" "前" ← まだ席がある場合

クエリ: "毎日 手書き すれ いい 相談 漢字 初期 書ける 日本語 勉強 僕 前"
         ↑ 最新メッセージのキーワードが常に含まれる
```

## 3. Acceptance Criteria

- **AC-1**: `recallQueryRecentMessageCount=2` で、最新 user message が 3 文字以上の有意味テキストなら、その message 由来の語が最終 query に最低 1 語は残る
- **AC-2**: 1 件前の長文 + 最新短文の組み合わせでも、最新短文が query から完全消失しない
- **AC-3**: `recallQueryRecentMessageCount=1` の場合、現在と同じ動作（single-message extraction）を維持する
- **AC-4**: 既存の attachment/noise 除去挙動を壊さない（`isDominant` / `cleanedText < 3` のスキップロジックは変更しない）
- **AC-5**: `perMsgKeywords` フィンガープリント（v0.4.23）が最新メッセージの語を反映していることと、最終クエリの語が一致することをログで確認可能
- **AC-6**: `npm run build:ts` PASS
- **AC-7**: `npm test` PASS。既知の失敗（`handleIdleFlush` など）がある場合は、事前にチケット化・再現手順固定化してから除外対象として明示すること

## 6. 用語

| 用語 | 意味 |

| 予約席 | 最新メッセージに確保された最低キーワード枠（デフォルト4語） |
