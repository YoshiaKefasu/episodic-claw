## 0. 目的

`recallQueryRecentMessageCount` のカウント起点を **「着地したばかりの最新ユーザーメッセージ = 1」** に固定し、
最新発話が Query から落ちるケースを構造的に防止する。

## 2. 問題の定義（ユーザー仕様）

カウント仕様は以下で固定する。

1. 最新ユーザーメッセージ（着地したばかり） = **1**
2. その1つ前 = **2**
3. そのさらに前 = **3**

`recallQueryRecentMessageCount=2` なら、必ず **[1,2]** が Query 入力対象。

---

## 3. 修正方針（Option A: 推奨）

### Option A（推奨）— Latest User Anchor を導入

`before_prompt_build` で `event.prompt` を正規化し、
`retrieveRelevantContext()` に `latestUserAnchor` として渡す。

retriever 側で window 構築時に:

1. 既存 `currentMessages` から user を抽出
2. `latestUserAnchor` が有意味（>=3文字）なら「最新 user 候補」として扱う
3. すでに末尾 user と同内容（正規化一致）なら重複追加しない
4. 不一致なら **末尾に仮想 user を追加**してから `.slice(-N)`

これで「最新 = 1」の起点を強制する。

#### Option A の利点

- 小差分で実装可能（`index.ts` + `retriever.ts`）
- 既存 `recallQueryRecentMessageCount` 仕様を壊さない
- timing 依存を1段吸収できる

### Option B（非推奨）— OpenClaw側フック順序に依存して待つ

plugin側では何もせず、`event.messages` へ最新userが入る保証を外部依存で待つ。

**非推奨理由**: 再発防止にならない。環境差（v2026.4.5/4.10 等）で再燃しやすい。

### 🛤️ Solution Options

#### Option A — Latest User Anchor（推奨）
**Approach**: `event.prompt` から `latestUserAnchor` を抽出し、window構築前に仮想最新userとして補正。  
**Implementation cost**: Low-Medium  
**Risk**: Medium（prompt正規化の誤判定リスク）  
**Why recommended**: 既存 `recallQueryRecentMessageCount` を壊さず、起点ズレを直接修正できる。

**Hardening (必須)**:
1. `normalizePromptAnchor()` で role/system/tool/code-block ノイズを除去
2. 正規化後 3 文字未満は棄却
3. 末尾userとの正規化一致で重複挿入を禁止
4. observability に `anchorRawPreview` / `anchorNormalizedPreview` / `anchorAcceptedReason|anchorRejectedReason` を追加

#### Option B — OpenClaw側順序保証待ち（非推奨）
**Approach**: plugin側で補正せず upstream イベント順序に依存。  
**Implementation cost**: Very low  
**Risk**: High（環境差で再燃）  
**When to choose**: なし（この不具合の再発防止要件に合わない）

- Pros: 確実性向上、環境差吸収、ログで追跡可能
- Cons: `event.prompt` 正規化ロジックの保守コストが少し増える
