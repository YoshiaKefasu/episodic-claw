## 0. 目的

本番環境で確認された2つの問題を修正する。

### Problem A: gemma-main が "unexpected model name format" で全6回無駄撃ち

- モデル名 `gemma-4-31B-it` が **大文字Bのため不正**
- Google Gemini API は小文字 `gemma-4-31b-it` のみ受理
- `GeminiDirectError.retriable === false` をcatchブロックが無視 → 6回の指数バックオフリトライが全弾浪費される

### Problem B: 全quality gateリトライ間隔が500msと短すぎてフェーズ急速枯渇

- 全品質ゲート（フォーマット/エコー/アンカー/文数/文字数等）のリトライsleepが一律500ms
- gate rejectが連続するとAttemptあたり500msしか間隔がなく、モデルが出力を改善する猶予がない
- 3回のcontent-gate reject → 早期ハンドオフが約18秒で発動
- OpenRouter側も同じ500msで、全モデル共通のボトルネック

## 4. リスクとトレードオフ

| リスク | 影響 | 緩和策 |
|---|---|---|
| sleep 60秒で1アイテム完了までの時間が伸びる | 最大で6回×60秒 = 6分の追加待機（全reject時） | モデルが合格を出せばsleepはスキップされる。出力品質が上がればreject回数も減る。 |
| 正常系（pass時）は影響ゼロ | — | sleepはreject時のみ |
| OpenRouterフォールバックまでの時間が伸びる | Google側が全6回×60秒 = 6分使う | ユーザー要件（Google経路優先）に合致。質より速さが必要なら設定値を下げられる余地を残す。 |
