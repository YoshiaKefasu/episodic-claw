## 3. 変更仕様（Fix C1〜C5）

### Fix C1 — デフォルト維持 + 明示設定で強制
- `narrativeLanguageOnFail` の default は **`softwarn` のまま維持**（いきなり全体昇格しない）。
- 強制動作は canary から `onFail=reask|handoff` を **明示設定**して段階導入。
- 目的: 一括デフォルト変更による保存率低下の blast radius を抑える。

### Fix C2 — reask 実装（Gate Result Routing パターン）

> **アーキテクチャ**: `applyQualityGates()` は純粋検査関数として変更せず、
> 戻り値 `QualityGateResult` に `isLanguageGate: boolean` を追加して routing 情報を伝播する。
> 実際の reask/handoff action は呼び出し元 `narrativizeWithModel()` で実行する。
> 既存の `isContentGate` routing パターン（L919-927）と同一アプローチ。

- **C2-a**: `QualityGateResult` に `isLanguageGate: boolean` を追加（既存 `isContentGate` と直交）
  - `isContentGate` = 品質問題（G3b/G4/G5/G6）
  - `isLanguageGate` = 言語ポリシー問題（G0 mismatch）
  - 両方 `false` = 形式問題（G1/G2/G3）
- **C2-b**: G0 mismatch 時、`onFail=reask|handoff` なら `{ pass: false, reason: "language-mismatch", isContentGate: false, isLanguageGate: true }` を返す
  - `onFail=softwarn` は従来通り fall-through（変更なし）
  - `contentGateEnabled=false` の場合も `isLanguageGate=true` で返すが、呼び出し元で softwarn フォールバックする
- **C2-c**: `narrativizeWithModel()` で `isLanguageGate` を判定:
  - `onFail=reask` + `contentGateEnabled=true` → 補正メッセージ付き userMessage を再構築して再試行
  - `onFail=handoff` → `return null`（即時 phase handoff）
  - `contentGateEnabled=false` → softwarn フォールバック（保存阻害しない）
- **C2-d**: reask 試行上限: `LANGUAGE_REASK_MAX=1`（1回だけ reask、2回目は handoff へ自動昇格）
  - reask の LLM 呼出しは既存の `maxAttempts` 予算から消費する（追加カウンター不要: KISS）
  - 例: `maxAttempts=12` → 通常試行11回 + 言語 reask 1回の構成
  - reask 時は `languageReaskUsed: boolean` フラグで2回目以降を抑制（attempt budget内で追跡）
- **C2-e**: reask 補正メッセージ: ハードコード定数
  ```typescript
  const LANGUAGE_NAME_MAP: Record<string, string> = { ja: "Japanese", en: "English", zh: "Chinese", ko: "Korean", id: "Indonesian" };
  const LANGUAGE_REASK_SUFFIX = (lang: string) =>
    `\n[IMPORTANT: Write the narrative in ${LANGUAGE_NAME_MAP[lang] ?? lang} language.]`;
  // 例: expectedLang="ja" → "...in Japanese language.]" → モデルが日本語で再生成
  ```
  - `LANGUAGE_NAME_MAP` は既存の `VALID_LANGUAGE_CODES` と同一キーセット（ja/en/zh/ko/id）
  - config キーは追加しない（YAGNI — ユーザーがカスタマイズする需要は低い）

### Fix C3 — handoff 連携（isLanguageGate 分類）

> **重要**: language mismatch は `isContentGate=true` ではなく `isLanguageGate=true` に分類する。
> `isContentGate=true` にすると `contentRejectCount` がインクリメントされ、
> 既存の content gate（G3b/G4/G5/G6）と混ざって early handoff を誘発する（SOLID-S 違反）。

- **C3-a**: `onFail=handoff` 時、`isLanguageGate=true` を返す（`isContentGate=false`）
  - 呼び出し元 `narrativizeWithModel()` で `isLanguageGate && onFail=handoff` を検知
  - `contentRejectCount` には影響しない（独立した routing）
- **C3-b**: language mismatch の即時 handoff — `isLanguageGate && onFail=handoff` なら
  即座に `return null`（phase handoff 発動）。3回累積を待たない。
- **C3-c**: `onFail=reask` で `LANGUAGE_REASK_MAX` を超えた場合も自動昇格して handoff
- **C3-d**: 既存の phase handoff ログに language 理由を追加:
  ```typescript
  console.log(JSON.stringify({
    source: "episodic-claw",
    event: "narrative-phase-handoff",
    phaseHandoffReason: "language_mismatch",  // 追加
    provider: phase.provider,
    itemId: item.id,
  }));
  ```

### ~~Fix C4~~ — unknown 判定ガード（削除: YAGNI）

> **削除理由**: 現在の G0 コード（`narrative-worker.ts:692`）は
> `langResult.lang !== "unknown"` で既に unknown をスキップしている。
> unknown は mismatch ブランチに**入らない**ため、専用分岐は不要。
> また `isReliable=false` も mismatch 分岐の内側にあり、confidence < threshold で
> フィルタ済みのため過剰 reject は起きない。
>
> 元の懸念は v0.4.28b の `hasCjkChars()` heuristic で G5/G6 側に対応済み。

### 🛤️ Solution Options

#### Option A — Gate Result Routing（推奨）
**Approach**: `applyQualityGates()` は品質検査のまま変更せず、**戻り値 `QualityGateResult` に `languageMismatch` フラグを追加**して routing 情報を伝播する。呼び出し元の `narrativizeWithModel()` でフラグに基づいて reask/handoff を判断する。

**実装コスト**: Low-Medium
**リスク**: Low
**Why recommended**: 既存の `QualityGateResult` は `{ pass, reason, isContentGate }` の3フィールド。`isLanguageGate: boolean` を1つ追加するだけで、reask/handoff の routing が呼び出し元で完結する。`applyQualityGates()` の純粋性を保ち、SOLID-S を守る。

**Concrete steps**:
1. `QualityGateResult` に `isLanguageGate: boolean` を追加（既存 `isContentGate` と直交）
2. G0 mismatch 時: `onFail=reask` → `{ pass: false, reason: "language-mismatch", isContentGate: false, isLanguageGate: true }` を返す
3. G0 mismatch 時: `onFail=handoff` → 同上（handoff 判定は呼び出し元で）
4. `narrativizeWithModel()` で `isLanguageGate` を判定:
   - `onFail=reask` + `contentGateEnabled=true` → 補正メッセージ付き userMessage を再構築して再試行
   - `onFail=handoff` → `return null`（即時 phase handoff）
   - `contentGateEnabled=false` → softwarn フォールバック（保存阻害しない）
5. reask 試行上限: `LANGUAGE_REASK_MAX=1`（1回だけ reask、2回目は handoff へ自動昇格）
6. reask 補正メッセージ: ハードコード定数 `LANGUAGE_REASK_SUFFIX = "\n[IMPORTANT: Write the narrative in {expectedLang} language.]"`

#### Option B — In-Gate Action
**Approach**: プラン通り `applyQualityGates()` 内で reask/handoff の action を直接実行する。

**実装コスト**: Medium
**リスク**: Medium
**When to choose this instead**: 検査と action の分離にこだわらない場合。ただし `applyQualityGates()` に `resolveUserPrompt()` や `this.client.chatCompletion()` の参照が必要になり、関数の責務が肥大化する。

**Concrete steps**:
1. `applyQualityGates()` の引数に `systemPrompt`/`client` 参照を追加
2. G0 mismatch 時に in-place で再試行
3. 関数の签名が膨張し、単体テストが困難になる

### ✅ Pro Recommendation

### 9.3 運用監査で発見・修正したバグ

**Bug 1: `LANGUAGE_REASK_MAX` 死定数（Dead Constant）**
- **症状**: `LANGUAGE_REASK_MAX=1` は定義されていたが、実際の再試行制限は `languageReaskUsed`（boolean）でハードコードされていた。定数を2に変更しても動作が変わらない（false confidence）。
- **修正**: `languageReaskUsed: boolean` → `languageReaskCount: number` に変更し、`languageReaskCount < LANGUAGE_REASK_MAX` で比較するカウンタ実装に修正。ログも `reaskCount=1/1` 形式に改善。
- **原則**: DRY — 定数と実装が矛盾していた。

**Bug 2: reask 後の `sleep(500)` 欠落**
- **症状**: 他の全ゲート reject（G1-G6）は `applyQualityGates` 内で `sleep(500)` しているが、G0 isLanguageGate の reask→continue には sleep がなく、即座に LLM 呼び出しが発生。rate-limit 懸念。
- **修正**: `continue` の前に `await this.sleep(500)` を追加。他ゲートと一貫性のある動作に修正。
- **原則**: KISS — 既存パターンとの一貫性。

**Bug 3: テストスタブの `detectLanguage` エクスポート欠落**
- **症状**: テストの lang-detect スタブが `detectLanguageDetailed` だけエクスポートしており `detectLanguage` が欠落。G5/G6 で `(0, lang_detect_1.detectLanguage) is not a function` 例外 → 3000ms リトライループ → テストタイムアウト。
- **修正**: 全スタブに `detectLanguage: () => "en"` を追加。
