# v0.4.30e Idle Poll Log Reduction

## 問題

NarrativeWorker の idle backoff ログが過剰。現在「20回に1回」のポーリングカウントガードだが、それでも **5分に1回、1時間に12回** 出力され続ける。

```
4:09:13 info [NarrativeWorker] Idle backoff: 380 empty polls, next in 15000ms
4:14:13 info [NarrativeWorker] Idle backoff: 400 empty polls, next in 15000ms
4:19:13 info [NarrativeWorker] Idle backoff: 420 empty polls, next in 15000ms
...
```

このログには **運用途中で確認する価値のある情報がほとんどない**（空ポーリングが続いていることしか示さない）。稼働確認以外の目的を持たないため、実質ノイズ。

## 現状コード

`src/narrative-worker.ts` L554-558:

```typescript
this.consecutiveEmptyPolls++;
this.nextPollDelayMs = Math.min(this.MAX_POLL_DELAY_MS, this.nextPollDelayMs * 2);

if (this.consecutiveEmptyPolls > 0 && this.consecutiveEmptyPolls % 20 === 0) {
  console.log(`[NarrativeWorker] Idle backoff: ${this.consecutiveEmptyPolls} empty polls, next in ${this.nextPollDelayMs}ms`);
}
```

- 空ポーリング20回ごと = 15秒 × 20 = 300秒 = **5分に1回**
- 5分 × 24時間 = 288回/日
- つまり現状でも「相当削った状態」だが、それでもユーザーにはノイズ

## 修正案

### A: 閾値段階的抑制（推奨）

閾値を超えたらログ間隔をさらに粗くする。

```typescript
// 最初の100回（〜25分）：20回ごとにログ
// 100回超え（〜8時間以上）：100回ごとにログ = 25分に1回
if (this.consecutiveEmptyPolls > 0 && (
  (this.consecutiveEmptyPolls <= 100 && this.consecutiveEmptyPolls % 20 === 0) ||
  (this.consecutiveEmptyPolls > 100 && this.consecutiveEmptyPolls % 100 === 0)
)) {
  console.log(`[NarrativeWorker] Idle backoff: ${this.consecutiveEmptyPolls} empty polls, next in ${this.nextPollDelayMs}ms`);
}
```

**トレードオフ:**
- 通常時（100回未満）: 5分間隔 → 変わらず
- 超長期アイドル時: 5分 → 25分間隔に抑制
- 実装: 3行追加、ロジック変更なし、リグレッションリスク極小

### B: 完全消去

```typescript
// 行ごと削除
```

**トレードオフ:**
- 簡潔だが、デバッグ時にポーリングが生きてるか確認できない
- リグレッションリスク: なし

### C: console.log → console.debug 化

```typescript
// if ブロックごと console.log → console.debug に変更
```

**トレードオフ:**
- OpenClaw のログレベルフィルタで抑制可能になる
- デフォルトでは表示されなくなる
- ログレベル設定の変更が OpenClaw 側に依存する

### 推奨: C + A の併用（本プラン）

**理由:**
- `console.log`→`console.debug` で env=development 時だけ表示（日常運用ではゼロノイズ）
- 段階的抑制で長時間アイドル時のログカウントも削減
- KASOU 環境（production）では debug ログがそもそも出ない想定

### リグレッション懸念

確認済み:
1. `console.log` → `console.debug`: KASOU（production）環境では `console.debug` はデフォルトで抑制される。ログが減るだけで機能影響なし
2. 条件式の変更: 既存の `% 20` ガードを維持しつつ、100 polls 超えで `% 100` に切り替えるだけ。テキストマッチのテスト（`runIdlePollLogStormRegression`）も新しい条件式に自動対応
3. `transport-retry.js` 欠落修正: 単なるファイルコピーリストへの追加。ロジック変更なし
