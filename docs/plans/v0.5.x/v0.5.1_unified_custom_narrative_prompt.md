# v0.5.1 — Unified Custom Narrative Prompt

> **Status**: Phases A–D and local Phase F verification implemented — code-reviewer APPROVE; Phase E Kasou migration not started
> **Created**: 2026-07-12
> **Scope**: Let one custom prompt file be the sole non-empty instruction source for narrative generation. Keep the existing two Kasou prompt files intact until live validation succeeds; do not delete any file in this work.

---

## 1. Goal

Kasou should use one custom file:

```text
~/.openclaw/prompts/episodic_claw_narrative.md
```

That file contains every narrative instruction, the previous-episode placeholder, the boundary-note placeholder, and the conversation-log placeholder.

When this mode is enabled, Episodic-Claw must send:

```text
system: [omitted — no text]
user:   [exact resolved contents of episodic_claw_narrative.md]
```

This is not “copy both files into one and send it twice.” There is one instruction-bearing prompt only: the user-role custom template.

### Target Kasou configuration

```json
{
  "narrativeSystemPrompt": false,
  "narrativeUserPromptTemplate": "/home/kasou_yoshia/.openclaw/prompts/episodic_claw_narrative.md"
}
```

`false` means **intentionally omit the system instruction**. It is distinct from an omitted property or an empty string, both of which preserve today’s default system prompt for backward compatibility.

---

## 2. Evidence

### A. Kasou currently has two separate custom files

`~/.openclaw/openclaw.json` configures:

```json
"narrativeSystemPrompt": "/home/kasou_yoshia/.openclaw/prompts/episodic_claw_narrative_system.md",
"narrativeUserPromptTemplate": "/home/kasou_yoshia/.openclaw/prompts/episodic_claw_narrative_user.md"
```

The current system file has four instruction lines. The user file has the detailed rules and `{previousEpisode}` / `{conversationText}` placeholders.

Meaning: the intended single-file content can be composed without inventing new narrative rules.

### B. Custom user template already fully replaces the default user template

`src/narrative-worker.ts:1435-1454` resolves a custom `narrativeUserPromptTemplate` directly, substitutes placeholders, and only uses `DEFAULT_USER_PROMPT_TEMPLATE` when no custom template exists.

Meaning: a unified custom user file already controls all detailed prompt content. No user-template merge feature is needed.

### C. Current system fallback prevents a true single-file mode

`src/narrative-worker.ts:1411-1415` returns `DEFAULT_SYSTEM_PROMPT` whenever `narrativeSystemPrompt` is empty.

`src/config.ts:237-241` resolves missing/empty prompt values to `""`.

Meaning: simply removing the system file from Kasou config would still inject the code default system sentence. A distinct explicit opt-out is required.

### D. Both providers currently always send a system instruction

`src/openrouter-client.ts:256-262` unconditionally includes `{ role: "system", content: systemPrompt }`.

`src/gemini-direct-client.ts:114-125` unconditionally includes `systemInstruction`.

Meaning: returning an empty string alone is insufficient for the stated goal. Both request builders must omit the system instruction when the resolved system prompt is intentionally empty.

### E. Omission is supported by Gemini request shape

Gemini API official documentation shows `generateContent` with only `contents`; `systemInstruction` is optional. Therefore omission, rather than `systemInstruction: { parts: [{ text: "" }] }`, is the correct request shape.

---

## 3. Design decision

Use `false` as the explicit no-system sentinel:

```ts
narrativeSystemPrompt?: string | false;
```

Why this is the smallest safe API:

1. Existing omitted property keeps current default behavior.
2. Existing non-empty string/path keeps current custom system behavior.
3. `false` is unambiguous in JSON and cannot be confused with an accidental blank file.
4. No new parallel config key is needed.

Normalization contract:

| Raw config value | Normalized value | Provider request |
|---|---|---|
| absent / `""` | `""` | existing default system prompt |
| inline string / `.md` path | resolved non-empty string | custom system instruction |
| `false` | `false` | omit system message / `systemInstruction` |
| any other type | `""` | existing default system prompt |

## 4. Implementation plan

### Phase A — Config contract and schema

Modify `src/types.ts`:

```ts
narrativeSystemPrompt?: string | false;
```

Update the comment so `false` is documented as intentional system-instruction omission.

Modify `src/config.ts`:

1. Keep `resolvePrompt()` for string path/inline resolution.
2. Add a narrow system-only normalizer, conceptually `resolveSystemPrompt(value, platform)`.
3. Return `false` only when raw config is exactly boolean `false`.
4. Delegate string values to existing `resolvePrompt()`.
5. Treat all other values as the current empty/default path.
6. Do not let `narrativeUserPromptTemplate` accept boolean `false`.
7. Wire the new normalizer at the existing output assignment; this exact call must change:

   ```ts
   narrativeSystemPrompt: resolveSystemPrompt(rawConfig?.narrativeSystemPrompt, platform),
   ```

   Calling existing `resolvePrompt()` directly would silently convert `false` into `""` and lose the no-system intent.

Modify `src/index.ts` TypeBox schema:

```ts
narrativeSystemPrompt: Type.Optional(
  Type.Union([
    Type.String({ description: "..." }),
    Type.Literal(false, { description: "Omit system instruction; use custom user template as the sole instruction source." }),
  ]),
)
```

Modify `openclaw.plugin.json` with the equivalent JSON-schema union and clear UI help text.

Modify the existing startup configuration summary in `src/index.ts`:

```ts
narrativeSystemPrompt=${
  cfg.narrativeSystemPrompt === false ? "(disabled: explicit no-system)"
  : cfg.narrativeSystemPrompt ? `(custom, ${cfg.narrativeSystemPrompt.length} chars)`
  : "(default)"
}
```

When `narrativeSystemPrompt === false` and `narrativeUserPromptTemplate` is empty after resolution, emit one concise configuration warning from this same startup/config-summary path:

```text
[Episodic Memory] narrativeSystemPrompt=false has no custom narrativeUserPromptTemplate; default user template remains active.
```

This warning is operationally useful but not an error: the default user template remains a safe fallback.

### Phase B — Narrative worker resolution

Modify `src/narrative-worker.ts`.

1. Change `resolveSystemPrompt()` return type to `string` while converting normalized `false` to the intentional empty string `""`.
2. Preserve current behavior for `undefined`, `""`, and non-empty strings:

```ts
false      -> ""                  // explicit no-system mode
"custom"  -> "custom"
undefined -> DEFAULT_SYSTEM_PROMPT
""        -> DEFAULT_SYSTEM_PROMPT
```

3. Do not change `resolveUserPrompt()` behavior, placeholder handling, boundary-note fallback, or timestamped conversation formatting.

### Phase C — Omit empty provider instructions

Modify `src/openrouter-client.ts`.

Build `messages` with the user message always present; prepend a system message only when `systemPrompt.trim().length > 0`.

```ts
messages: [
  ...(systemPrompt.trim() ? [{ role: "system", content: systemPrompt }] : []),
  { role: "user", content: userMessage },
]
```

Modify `src/gemini-direct-client.ts`.

Build the request body with `contents` and `generationConfig` always present. Add `systemInstruction` only for a non-empty system prompt.

```ts
...(params.systemPrompt.trim()
  ? { systemInstruction: { parts: [{ text: params.systemPrompt }] } }
  : {}),
```

Do not send an empty system role/message. This is how the unified custom file remains the sole instruction text for both provider paths.

## 5. Compatibility matrix

| Existing configuration | Behavior after change |
|---|---|
| no `narrativeSystemPrompt` | unchanged: code default system prompt + existing/default user prompt |
| non-empty system string/path | unchanged: custom system + user prompt |

| `narrativeSystemPrompt: false` without custom user file | valid but discouraged: only default user template remains; document via warning or schema description, do not crash |

## 6. Risks and safeguards

### R1 — accidental loss of all narrative instructions

Risk: operator sets `narrativeSystemPrompt: false` but forgets the user template.

Safeguard: retain the default user template as a safe fallback; log a concise startup warning when no-system mode has no custom user template.

### R2 — provider request semantic mismatch

Risk: passing `systemInstruction: ""` is not equivalent to omission.

Safeguard: test actual OpenRouter request messages and Gemini JSON body; omit fields entirely when empty.

### R3 — prompt rules accidentally duplicated

Risk: config points both fields at the unified file.

Safeguard: migration explicitly uses `false` for system, never the unified file path. Verify outgoing request has only user instruction content.

### R4 — boundary note becomes detached

Risk: one-file rewrite omits `{boundaryNoteBlock}`, relying only on fallback append.

Safeguard: include the placeholder explicitly between previous episode and log in the new file; test this exact resolved layout.

### R5 — destructive rollback loss

Risk: deleting old prompt files prevents quick comparison/rollback.

Safeguard: this plan creates one new file and leaves both old files untouched. Any deletion needs a separate approval.

1. `narrativeSystemPrompt: false` is schema-valid and reaches normalized config unchanged.
2. OpenRouter and Gemini omit their system instruction completely in no-system mode.
3. Existing configurations remain behaviorally unchanged.

5. The unified file explicitly owns `{previousEpisode}`, `{boundaryNoteBlock}`, and `{conversationText}` placement.
